# memotty API のエラーは RFC 9457 Problem Details の形で返す

memotty API がエラーを返すときは、RFC 9457 Problem Details の形（`type`・`title`・`status`・`detail`。バリデーションエラーのときは、どの項目がなぜ不正かを並べた `errors` も付ける）を使う。エラーの形はすべてのクライアントとの契約になり、ADR 0003 で破壊的変更をしないと決めたので後から変えにくい。そのため独自の形ではなく、標準化されていて第三者にも意味が通じる形を選んだ。

## Considered Options

- **独自の形（`{ error: { code, message } }`）**：シンプルだが、項目の意味を自分で定義して説明し続ける必要がある。大手の公開 API（Google・Microsoft・Vercel など）で最も多い形だが、提供元ごとに中身が違い、決まった仕様は無い。
- **フレームワークやバリデータの既定の形のまま**：TS の主要なフレームワーク（Hono・Express・Fastify・NestJS・tRPC・oRPC・Elysia）は、どれも既定では Problem Details を返さず、形はばらばら。`@hono/standard-validator` の既定の 400 は入力をそのまま `data` に入れて返すので、パスワードなどが漏れる。形もライブラリの都合で変わりうる。
- **`hono-problem-details` を使う**：機能はそろっているが、メンテナが 1 人の若い 0.x のパッケージで、`@hono/standard-validator` の peer dependency が `^0.2.0` と合わず、RPC の型に 400 が載るかも分からない。必要な処理は数十行なので自前で書く。

TS のエコシステムでは Problem Details は主流ではない（2026-10 時点。専用のライブラリの週間 DL は数千）。それでも、標準化された形はこれだけで、どの形を選んでも自分で組み立てる手間は変わらないため、Problem Details を選んだ。

## Consequences

- `Content-Type: application/problem+json` を使ったときに、Hono RPC の `parseResponse()` と型推論が期待どおり動くかは、実装を始める前に確認する。動かない場合は、形は RFC 9457 に合わせたまま、Content-Type だけ `application/json` にする。
- 拡張メンバー（`errors` など）は問題の種類（`type`）ごとに定義する（RFC 9457 §3.2）。ステータスコード以上の意味が無いエラーは `type` を `about:blank` にし、`title` を HTTP のステータスの名前（`Not Found` など）にして、拡張メンバーは付けない。
- 問題の種類は、`https://memotty.app/problems/` の下の絶対 URI で定義し、次の表に `type`・`title`・ステータスコード・拡張メンバーを書く（§4 で必須）。URI の先のドキュメントは必須ではないので、必要になったら用意する。

| `type`                                          | `title`              | ステータス | 拡張メンバー                                                                                                                                                                                                                                                                               |
| ----------------------------------------------- | -------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `https://memotty.app/problems/validation-error` | リクエストが不正です | 400        | `errors`：不正な箇所の配列。各要素は `detail`（人が読むための説明。クライアントは解析しない）と、クエリパラメータが原因なら `parameter`（パラメータの名前）。どの項目にも属さないエラーは `parameter` を省く。ボディの項目を指す書き方は、ボディを検証するエンドポイントを作るときに決める |
