# コードは人間が書き、AI は補助に徹する

memotty はプロダクト開発であると同時に、開発者がソフトウェアエンジニアリングのスキル（設計判断、テスト、TypeScript / React / Hono の書き方、コーディングそのもの）を伸ばす場でもある。そこで、ソース・テスト・設定ファイルは人間が書き、AI は要件や設計の壁打ち・情報の調査・ドキュメント作成・依頼されたときのレビューを担当すると決めた。AI に実装を任せると開発は速くなるが、学習の機会が失われるため、開発のスピードよりも学習を優先する。

## Considered Options

- **AI が実装も担当し、人間はレビューする**：最も速いが、自分で書く経験が積めない。
- **ペアプログラミング形式で AI が一部を書く**：どこまでを AI に任せるかの線引きが会話ごとに揺れ、結局 AI が書く範囲が広がりやすい。

## Consequences

- AI がファイルを書くのは Markdown の文書だけ。例外は、人間がそのタスクについて明示的に依頼したときに限る。
- AI がコードを書く前提のスキル（`implement`、`tdd`、`prototype` など）はこのプロジェクトでは使わない。
- 指示だけでは長い会話の中で破られうるため、Markdown 以外への Edit / Write に人間の承認を必須とする Claude Code の hook で機械的に守らせる。hook も設定ファイルなので人間が書く。
- コミットと push は依頼されたときに AI が行ってよい（ブランチ + PR）。マージと本番デプロイは人間が行う。
